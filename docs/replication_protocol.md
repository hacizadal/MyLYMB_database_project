# Replication experiment (measured on 2026-11-25)

Run `bash replication_benchmark.sh` from the project root with the Python environment active and Docker running. Defaults: 100,000 rows, three repetitions per configuration; override with `ROWS=1000000 REPEATS=5 bash replication_benchmark.sh` if needed. The script uses a unique Compose project, temporary credentials, localhost ports 13306/13307 and separate disposable volumes. It removes only that project's containers and volumes on exit. Existing benchmark results and the original database are not touched.

Both servers run MariaDB 11.4.13 with 512 MiB buffer pools. The primary uses row binlogging, and the replica uses a single default applier configuration. Each run seeds a fresh table and waits for the replica to reach the primary binlog position. The same VARCHAR(30) to VARCHAR(60) widening is used for INSTANT, COPY/NONE and COPY/EXCLUSIVE, isolating algorithm/lock choice rather than changing the DDL operation. A fixed shuffled order reduces order bias. One writer updates a row and a heartbeat in one transaction, with 20 ms pacing. A sampler reads heartbeat sequences and replication status approximately every 100 ms. Baseline is 3 seconds, post-ALTER workload 5 seconds.

Results include per-run write and lag CSVs, individual results, grouped summary and sequence-gap plot. The sequence gap is an approximate snapshot (replica read precedes primary read); heartbeat age includes primary write stalls and sampling delay, so it is not pure replication latency. First sampled zero gap after ALTER is not proof of sustained recovery; a blank means none was observed. Drain wait measures catch-up after stopping the workload. Final verification compares ordered row SHA-256, row count, table definition and heartbeat on both servers after a binlog position barrier. Any worker error or inconsistency fails the benchmark. Raw traces from interrupted runs may remain. Short INSTANT operations can be missed by the sampler. Local containers share hardware, and this experiment does not represent network-separated production replicas.

Nine runs completed successfully. See [individual results](../results/replication_20261125_111030/replication_results.csv) and [summary](../results/replication_20261125_111030/replication_summary.csv). All nine final consistency checks passed; sampled I/O and SQL error codes were zero. The README reports individual durations, median and sample standard deviation.
